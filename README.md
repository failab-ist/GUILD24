# 던전 앞 편의점 · 길드24 v0.3

첨부된 v0.1을 최신 추가 설계서에 맞춰 수정한 플레이 빌드입니다. 핵심 시스템 구현과 자동 회귀 검증을 포함합니다. 사람의 반복 플레이와 최종 밸런스·아트 완성 판정은 남아 있습니다.

## 실행

압축을 풀고 `index.html`을 브라우저로 엽니다. 실제 게임은 `dist/index.html`입니다. 설치·로그인·외부 API·외부 폰트 없이 실행됩니다. 휴대전화에서 파일 실행이 제한되면 정적 웹서버에 올려 사용하세요.

개발용 서버는 `node tools/preview.cjs`입니다. 저장은 브라우저와 실행 주소별로 분리됩니다. 주소나 기기를 옮길 때 설정에서 JSON 저장 내보내기·가져오기를 사용하세요. 기본 소리는 꺼져 있습니다.

## 한 Run

1. DAY0 점포지원 3개 중 하나를 무료로 선택합니다.
2. 오늘 방문 인원과 열린 게이트를 보고 수량을 골라 발주 확정합니다. 손님 신원은 영업 전 공개하지 않습니다.
3. 상품을 선택해 바가지 150%, 정가 100%, 반값 50% 중 하나로 판매합니다. 유물의 본사 보증이 있는 경우 그 지원액을 따로 표시합니다.
4. 현재 재고 전체에서 선택할 수 있으며, 같은 상품은 가까운 유통기한 순서로 나갑니다. 보급은 기본 2칸, Lv10부터 3칸입니다.
5. 밤에는 모험가별 결과를, 마감에는 점포 장부를 봅니다. 귀환 카드는 건너뛸 수 있습니다.
6. DAY5·10·15·20·25에 점포지원 후보 3개가 갱신됩니다. 다음 갱신 전까지 구매를 보류할 수 있습니다.
7. DAY30에는 마지막 점포지원·발주·최종팀 보급에 남은 Gold를 배분합니다. 최대 3명을 마왕성으로 보냅니다.

허세는 실제 목적지를 바꾸지 않습니다. 여러 게이트 중 더 위험한 곳으로 간다고 과장할 수 있고, 바가지 구매 의사가 상대적으로 높습니다. 구매 보장이나 지갑 제한 면제는 아닙니다.

## 포함된 변경

- 점포지원 30종, 여섯 운영 방향, 7개 구매 Window, 저장 가능한 고정 후보·가격과 보류.
- 5개 Dungeon Family × 3 Tier, Seed별 초기 Family 구성과 시기별 Tier·Gate 수 변화.
- 상품 27종, 직업 6종(기본 4 + 기존 메타 해금 2), 특성 20종과 상호배제.
- 반값·정가·바가지 가격, 단골 투자, 거절 후 낮은 가격 재시도, 시식 행사 이관.
- 실제 효과 표시, 판매 전후 비교, 모바일 세로 정보 배치, 묶음 발주와 자금 합계.
- 개별 귀환 카드와 별도 마감, 제한된 관계 발견, 기본 무음의 로컬 합성 BGM·효과음.
- Save schema 3. 과거 25%·무료 거래 기록 보존, 과거 재고의 실제 원가 불명 표시.
- 업무모드 제거. 기존 Seed RNG·직렬화 상태·소모품·탈출·부상 방어·부활 경로 유지.

## 검증과 문서

```bash
node tests/core.cjs
node tests/regression.cjs
node tests/coverage.cjs
node tests/balance.cjs 300
node tools/report.cjs
```

`npm test`도 같은 테스트를 실행합니다. Node는 개발 검증에만 필요합니다. 게임 안 `Ctrl+Shift+D`는 개발 진단 화면입니다.

- `PLAYTEST.md`: 실제 확인 범위와 미완료 수용 기준.
- `reports/AUDIT.md`: 원본 문제 분류, 변경·유지·위험·저장 호환.
- `reports/RELICS.md`: 30종 기능·가격·최종일 적격성.
- `reports/ITEM-PRICES.md`: 전체 상품 50/100/150 가격·마진·역할.
- `reports/COVERAGE.md`, `reports/TRAITS.md`: 직업·던전 대응과 특성 점검.
- `reports/BALANCE.md`: 4,800 Run, 분모·DAY 스냅샷·가격·유물·던전 지표.
- `reports/operating-experiment.json`: 운영비 한 변수 비교. 게임의 기본값을 변경하지 않는 진단 스크립트입니다.

## 구조

`data/catalog.js`는 기존 카탈로그와 가격 규칙, `data/relics.js`는 새 유물·계열·대응 상품 데이터입니다. `systems/shop.js`가 방문·발주·판매·밤을, `systems/relics.js`가 구매 창과 유물 적용을 담당합니다. `systems/dungeon.js`의 실제 계산을 `ui/presentation.js`와 `ui/app.js`가 표시합니다. UI용 계산식을 별도로 만들지 않습니다.

숫자는 검증용 시작값입니다. “정가가 늘 최선인가”, “약한 NPC를 살린 장기 가치가 충분한가”, “중후반 도달이 너무 쉬운가”는 현재 보고서의 남은 핵심 과제입니다.
