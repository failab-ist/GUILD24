## CROSS-RUN CORE — v2.8

Cross-run progression has two primary active growth identities:

### STORE GROWTH
```text
Run economy
-> Store Capital
-> permanent Decoration ownership
-> pre-Run Decoration loadout
-> changed store-operation options in the next Run
```

Store Growth must remain a **store-operation** progression channel.
It must not become an account-wide raw combat-stat ladder.

### JOB MASTERY
```text
Boss CLEAR with Job
-> Job Mastery
-> that Job's existing future spawn-growth channel
```

Job Mastery remains the successful-conquest channel and is not purchased with Store Capital.

## RUN / META BUILD SEPARATION

`RELIC` = Store Build created inside the current Run.

`DECORATION` = permanent cross-run collection from which the next Run's Meta Build is selected.

These roles must remain distinct.

## DECORATION INFLATION BOUNDARY

Owning more Decorations must not increase the number of simultaneously active passive effects without a separately approved design change.

Each Decoration belongs to one fixed Slot.
At most one Decoration per Slot is active in a Run.

Future content should primarily add alternatives / sidegrades inside existing Slots rather than stack unlimited permanent bonuses.

## FIRST-CLEAR BOUNDARY

Fresh Store / zero Decoration must remain capable of reaching Final and clearing a first Boss through strong play and valid RNG.

Cross-run Store Growth should make Final access progressively more realistic, not convert an impossible base game into a possible one.

## RETIRED ACTIVE LAYER

v2.7 Franchise Grade / Franchise Achievement / Start Contract are retired from active v2.8 progression.

They are preserved as inactive historical Source/Design assets under the archive rule owned by `META_v2.8.0.md`.
They must not remain hidden active progression.
