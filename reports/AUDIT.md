# 원본 감사와 변경 판단

최신 추가 설계서를 우선했다. 초판 ZIP에는 그 이전 PASS 변경이 없었다. 기존 코드 전체를 프레임워크로 바꾸지 않고 순차 script 구조, Stable ID, Seed RNG, 직렬화 GameState를 유지했다.

## 구현 의존 순서

1. 가격·원가·거절·저장 및 입력 검증을 먼저 통일.
2. 최소 UI와 도착 시점 정보 공개 정리.
3. 점포지원 Window와 30종 카탈로그·실제 hook 연결.
4. Family/Tier와 Coverage. 기존 25상품을 먼저 대조하고 로프·사탕 2종만 추가.
5. 방문객·지갑·단골도·생환, 지식·원정 결과·마감 장부 연결.
6. 코어 회귀, 자동 정책 계측, 브라우저 흐름 검증.
7. 문구·이름·모바일 가독성·기본 음향 정리 및 패키징.

## 유지한 것 / 단순화한 것

Seed RNG, 원정 계산과 UI의 분리, 상품 ID, 직업 6종, 기본 2/Lv10 3칸, 1회 소비품, 생환·사망·부상·귀환석·부활·보험, 기존 Meta 해금은 유지했다. 신규 관계 지식에 영구 능력 보너스는 추가하지 않았다. 기존 계정 등급의 작은 시작 혜택은 남아 있다.

업무모드, 일반 무료 판매, 고정 최고난도 허세 배정, 무의미한 희귀상품 의사 보너스를 제거했다. 새 결제 미니게임·실시간 전투·직업별 유물 Build·밈 전용 저장 카운터·새 라이브러리는 만들지 않았다. 문화 밈은 불확실한 레퍼런스를 억지로 넣지 않았다.

## Save / History

schemaVersion 3. 자동저장 키를 유지하며 v1/v2/v3를 검증·변환한다. 과거 거래 모드·paid는 그대로 남고 화면에서 이전 거래로 구별한다. refused 구 키만 새 구분자 형식으로 변환하며 구 discount는 새 half와 구분한다. 원본 v1 fixture의 가져오기와 다음 날 진행을 테스트했다.

새 유물 Window의 ID·정수 가격·구매 상태를 저장하므로 불러오기가 재추첨을 일으키지 않는다. 과거 진행 중 보유 설비는 이름·효과가 새 설계에 맞춰 일부 바뀐다. 기존 효과를 전부 영구 동결하는 별도 구 엔진은 만들지 않았다. 초판 런을 끝까지 옛 규칙으로 재생하는 호환을 뜻하지 않는다. 저장 삭제나 강제 Reset은 하지 않았다.

기존 재고의 원가가 불명확하면 확인 가능한 원가·이익에 합산하지 않는다. 새 Run의 초기 재고는 시작 패키지의 표준 원가로 기초 재고 가치를 기록하며, 당일 현금 발주 지출에는 넣지 않는다.

## 위험과 남은 작업

유물별 수치는 시작값이다. 음식·음료 강화는 부작용도 함께 키우며, 설명에 명시했다. 복수 곱연산은 발주 할인 최저 45%로 제한한다. 현재 자동 정책은 사람의 전문적 운영·보스 준비를 완전히 구현하지 않으며, 조건부 성과를 인과 ROI로 오해하면 안 된다.

일부 PASS 2 품질 요구와 PASS 3 수용 기준은 아직 사람의 플레이로 검증되지 않았다. 핵심 시스템 구현 완료와 최종 게임 디자인 검증 완료를 구분한다. 자세한 범위는 PLAYTEST.md와 BALANCE.md를 따른다.
