## 10. BALANCE FINDING / UNRESOLVED

### FINDING — hub가 현재 균형에서 순손해다

단독 장착 시 파산 47.3% → **60.0%**, 정산액 584 → **476**(전 조합 최저), 매출 −5.1%.
D25/D30도 개선되지 않는다(7.7%→6.7%, 2.7%→2.7%).

역할 자체는 Canonical 의도대로 작동한다 — 방문객을 가장 많이 늘리고(4.75/일) 비용을 실제로
치른다. 문제는 **치른 비용만큼 돌려받지 못한다**는 것이다. `board+hub` 조합에서는 정산액
963으로 board 단독(807)보다 낫지만, hub 단독은 어떤 지표로도 미보유보다 낫지 않다.

`overheadBase +20%`는 User 확정 수치이므로 **임의로 조정하지 않았다.** 방향만 적는다:
비용을 낮추거나(예: 15%), 확률을 올리거나(예: 40% +1), 운영비 증가가 방문객 증가와 같은
Day에만 발생하도록 묶는 방법이 있다. 어느 쪽이든 Design 결정이다.

### UNRESOLVED

- **Boss**: D30 표본이 arm당 8~42건으로 Boss별 판정 불가. `INSUFFICIENT SAMPLE` 유지.
- **위 hub 조정 방향**은 Design 결정이며 이번 Pass에서 수치를 적용하지 않았다.

### 하지 않은 것

- Production Source를 변경하지 않았다. 모든 후보는 런타임 override 후 복원이다.
- Gate / Wallet / Hazard Counter / Decoration / Relic의 새 후보를 만들지 않았다.
- Decoration 효과를 위해 Relic id를 facilities에 주입하거나, 보유 처리·후보 제거·slot 소비를
  하지 않는다. 이전 Pass harness에 남아 있던 그 처리는 제거했다.
- 확률 판정은 Run seed와 Day로 파생한 별도 스트림에서 뽑아 비교 대상 외 RNG가 밀리지 않게
  했다. 이 스트림 분리는 측정 장치이며 Production Design으로 승격하지 않는다.
