# BGM / SFX 믹스 — 퀵패치 (User 2026-09-29, 플레이 피드백)

## User 피드백

- BGM · SFX 위계를 더 분명하게. SFX가 더 잘 들리게. BGM을 줄일지 SFX를 키울지는 WORK 판단.
- NIGHT는 더 줄인다. 체감상 더 크다.
- 페이즈가 바뀔 때 새 곡이 뚝 시작한다.

## 측정 방법

- 페이지의 실제 출력(마스터 버스)을 헤드리스 크로미움에서 녹음했다.
- K 가중 근사, 100 ms 창의 순간 음량으로 비교했다. 짧은 효과음은 400 ms 창에서 실제보다 작게 잡히기 때문이다.
- 스크립트는 개발용이라 저장소에 넣지 않았다.
  - 녹음: 마스터 탭 → WAV
  - 분석: ffmpeg `highpass 38 Hz + highshelf +4 dB @ 1.68 kHz`, numpy 100 ms 제곱평균

## 2차 — 평탄화 (User 2026-09-29, 청취 후)

User 청취 결과:
- BGM을 더 줄여야 한다.
- 효과음이 평탄하지 않다. 너무 큰 것도 있고 안 들리는 것도 있다.
- 깔린 BGM과 겹치는 것도 고려해야 한다.

측정 방법 (`tools/qa-sfx-mix.cjs`, `npm run qa:runtime`에 포함)
- 실제 엔진을 오프라인으로 렌더한다. 효과음 하나씩, BGM 슬라이더는 0.
- 크기: K 가중(BS.1770) 100 ms 창의 최대값
- 들림: 1/3 옥타브 대역별로, 그 효과음이 울리는 페이즈 곡의 큰 구간(90퍼센타일)보다 얼마나 위에 있는지. 더킹을 빼고 계산하고, 가장 잘 들리는 대역을 쓴다.

조정
- BGM −27 → **−30 LUFS** (NIGHT −33)
- 효과음마다 레벨 표(`LEVEL`)를 두고 등급 목표에 맞췄다. 음색은 그대로다.
- 버스 +6 dB(`SFX_GAIN`)는 표에 흡수했다. 효과음 버스는 플레이어 슬라이더 값 그대로다.

| 등급 | 목표 | 전 (편차) | 후 |
|---|---|---|---|
| 결과 | -17 | -37.5 ~ -23.0 (14.5 dB) | -17.0 ~ -17.0 |
| 결정 | -19 | -42.4 ~ -21.8 (20.6 dB) | -19.0 ~ -19.0 |
| 일반 동작 | -23 | -45.6 ~ -25.4 (20.2 dB) | -23.0 ~ -20.1 |
| UI | -27 | -35.0 ~ -25.7 (9.3 dB) | -27.0 ~ -24.1 |
| 연타 | -29 | -39.7 ~ -37.5 (2.2 dB) | -26.1 ~ -26.1 |

- 전 측정은 레벨 ×1, BGM −27 조건이다. 후 측정은 BGM −30 조건이다.
- 전체 편차: 전 23.8 dB(−21.8 ~ −45.6) → 후 등급별 목표 ±3 dB 이내
- 들림 여유: 결과·결정 등급은 모두 +8 dB 이상, 일반 동작은 +5 dB 이상
- 피크: 가장 큰 효과음과 가장 큰 곡 피크를 합쳐도 −3.2 dBFS

FINDING (User 결정 필요 — 음색 문제, 이번 범위 밖)
- `ui`(자주 쓰는 UI 클릭): 등급 상한(+3 dB)까지 올려도 음악 대역보다 +0.2 dB 위에 그친다.
- `quantity` · `quantset`(수량 틱): 상한에서도 −12.5 dB. 짧은 클릭 샘플이라 음악에 묻힌다.
- 더 올리면 등급 순서가 깨진다. 해결하려면 더 밝고 또렷한 소리(음색)로 바꿔야 한다.
