## 1. 콘티 — 30초, 손님 한 명. 첫 컷부터 플레이 화면

| 초 | 화면(실제) | 자막 (3인칭 · 한 번에 한 메시지) | 소리(무음 재생 전제, 있으면 보너스) |
|---|---|---|---|
| 0~5 | **SALE 화면부터**: 손님 · 진열대 · 가게가 한 프레임 → 마왕 관련 실제 화면 1컷(D25 공개 또는 FINAL 입구) 짧게 | **단 30일.** / **편의점에서 시작되는 마왕 토벌.** | BGM 인 |
| 5~12 | 손님 목적지 판 확인 → 대응 상품 탭 → 트레이 → 가격 셋 → 선택 → 건네주기 | **당신이 건넨 물건 하나가,** | 선택 · 판매 cue |
| 12~20 | **같은 손님**의 NIGHT: 얼굴 · 도장 · 일어난 일 · 원인 줄(두건) · 변화. 자막을 먼저 띄우고 지운 뒤 원인 줄에 집중시킨다. 노출 시간은 러프컷에서 정함(2초 고정 아님). 8초 안의 우선순위: 같은 손님임을 알아보기 → 판 상품의 영향 읽기 → 자막 | **그들의 생사를 가른다.** (먼저 띄우고 제거) | stamp |
| 20~27 | **같은 손님이 든** 출전 명단 — 앞에서 본 얼굴을 알아볼 길이로 → 교전 → 균열 → 붕괴 → `마왕이 쓰러졌다.` 읽을 시간 1초+ | **키워낸 단골들과 함께,** / **마왕을 쓰러뜨려라.** (이후 실제 화면만) | 교전 cue · settle |
| 27~30 | 타이틀 로고 + 장르 한 줄 | **던전 앞 편의점** / 턴제 경영 로그라이트 | BGM 아웃 |

- 자막 5장 — **제미나이 B안(로그라이트 감성형) 베이스 + A안 한 어절 섞음**(User 2026-10-01). `상점` → `편의점`(우리 정체성), `키워낸`은 A안에서. 5~12와 12~20은 한 문장이 둘로 이어진다(물건 하나가, → 생사를 가른다). 숫자는 `30일` 하나. "설원" · "밤이 되면 답이 온다"처럼 촬영 사례 · 분위기 문장은 뺐다(영상이 팔 것은 "손님에 맞춰 고르는 재미").
- 게임 화면 비율 0~27초 = 90%. 권장 취지(실제 플레이 중심) 충족은 러프컷에서 확인 — 판매 · NIGHT가 중심이라 방향은 맞다. 로고 3초.
- 토벌 구간이 7초를 넘으면 출전 명단을 바로 빼지 않고 **교전의 대기 · 반복 구간을 먼저 컷 편집**한다. 끝 카드 3초 고정.
- 자막 폰트: 게임 폰트 고집하지 않고 작은 화면 가독성(굵기 · 크기) 우선.

## 2. 만드는 방법 — 실제 도달한 상태만
- **상태**: 게임 엔진을 페이지 안에서 봇 정책으로 D30까지 실제 플레이시켜 만든다(발주 · 판매 · 보내기 · 밤 · 마감 전부 정상 API, 판정 주입 없음). `qa-final-*` 하네스는 판정을 핀하므로 쓰지 않는다.
- **시드 조건(단순화)**: 어느 날이든 ① 손님 X에게 대응 상품을 팔고 ② 그 밤 X의 카드에 성공/대성공 + 원인 줄(그 상품) ③ X가 D30 최종 출전 파티에 있고 ④ 토벌. D1 고정 아님. **조건에 맞는 실제 플레이 기록을 선정하고, 그 기록이 브라우저에서도 동일하게 재현되는지 확인한다.** 재현이 다르면 시드를 바꾸기 전에 시작 상태 · 입력 순서 · 대기 시간이 같은지 먼저 확인한다(재현 문제를 숨기지 않기 위해). 탐색은 촬영 가능한 기록을 확보하면 종료. 홍보용 기록이며 QA · 밸런스와 무관하다고 기록.
- **캡처**: 5~12초 구간으로 5초 시험 — ⓐ 스크린샷 연속(dpr 3) ⓑ `recordVideo`. 선명도 · 모션 간격으로 **WORK가 고르고 보고**. ⓑ가 충분하면 가상 시간은 만들지 않는다.
- **소리**: BGM 한 곡 + 그 동작에 게임이 실제 쓰는 cue 파일(`audio.js` 매핑 기준). 합성 cue는 OfflineAudioContext 렌더 시험, 안 되면 BGM만. 무음 재생이 기본이라 소리는 보너스.
- **자막 카드**: HTML → PNG(게임 폰트) → ffmpeg overlay. 한 카드 2초 이상, NIGHT 카드는 2초 뒤 제거.
- **조립**: ffmpeg(`imageio-ffmpeg` 확인됨). 러프컷(540×960) → User 리뷰 → 고화질 1080×1920 30fps H.264. 버전 표식은 캡처 · 영상에서만 숨김, 촬영 HEAD 기록.
- **빌드 일치**: 출시 안드로이드 빌드(Capacitor, 같은 dist)와 화면 · 조작 · 콘텐츠가 같은지 APK가 나오면 한 번 대조. 스토어 영상의 약속 = 설치한 게임.
- **스토어 스크린샷 2차**는 같은 시드일 필요 없음. 각자 실제 게임을 정확히 보여주면 된다(같은 상태 재사용은 편의).

## 3. 배치 (순서만)
1. 시드 탐색 + 5초 시험 제작 + 5컷 첫 프레임 → User 리뷰(콘티 확정, 캡처 방법은 WORK 보고).
2. 전체 캡처 + 자막 + 소리 → 러프컷 30초 → User 리뷰.
3. 수정 → 고화질 → 유튜브 업로드(User) → Play Console 링크(User). 종료 조건 = 읽히고 오류 없음.
