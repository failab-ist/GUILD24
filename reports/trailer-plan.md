## 1. 산출물 · 순서
A 세로 30초(1080×1920, **구글 플레이 스토어 영상 — 유튜브 업로드 후 링크**) → B 15초(A 뒤 다시 짬) → C 가로(후순위). 끝 카드는 배포처마다 하나: 스토어판 = 타이틀 + 한 줄, itch판 = 타이틀 + 체험판 안내(끝 카드 4초만 교체).

## 3. 만드는 방법 — 실제 도달한 상태만

### 3-1. 상태는 실제 플레이로 만든다 (주입 없음)
`qa-final-*` 하네스는 판정을 고정값으로 핀하므로 쓰지 않는다. 대신 **게임 엔진을 페이지 안에서 봇 정책으로 D30까지 실제 플레이**시킨다(`Debug.simulate`의 playRun과 같은 행동을 브라우저의 `Guild24.game`에 그대로 적용 — 발주 · 판매 · 보내기 · 밤 · 마감이 전부 정상 API). 조건을 만족하는 **시드를 찾는다**: ① D1에 설원(냉기) 게이트 손님이 있고 창고에 두건이 있음(첫 판 레슨이 대응 상품을 넣어 주므로 가능성 높음) ② 그 손님의 D1 밤이 성공 또는 대성공이고 원인 줄에 두건이 찍힘 ③ 그 손님이 D30 최종 출전 파티에 있고 ④ 토벌. 시드 탐색은 헤드리스 시뮬레이션으로 수백 개를 돌려 고른다. **판정이 다르면 시드를 바꾼다. 결과는 바꾸지 않는다.** 이 시드는 홍보용이며 QA · 밸런스 수치와 무관하다고 기록에 적는다.
### 3-2. 캡처
5초 시험(8~14초 구간)을 ⓐ 스크린샷 연속(dpr 3) ⓑ `recordVideo` 둘로 뽑아 **WORK가 선명도 · 모션 간격으로 고르고 보고**한다. ⓑ가 충분하면 가상 시간 방식은 만들지 않는다.
### 3-3. 소리
BGM 한 곡(§5). 효과음은 **그 동작에 게임이 실제로 쓰는 cue**를 `audio.js`의 매핑에서 읽어 같은 파일을 타임라인에 놓는다(이름만 보고 붙이지 않음). 교전 · 붕괴 · 도장 중 합성 cue는 `audio.js` 합성을 OfflineAudioContext로 렌더해 wav로 뽑을 수 있는지 시험. 안 되면 그 구간은 BGM만.
### 3-4. 자막 카드
HTML → 같은 브라우저에서 PNG(게임 폰트). ffmpeg overlay. 모바일 실제 크기에서 읽을 시간 확보(한 카드 2초 이상).
### 3-5. 조립 · 리뷰
ffmpeg(`imageio-ffmpeg` 확인됨). 러프컷(540×960, 자막 포함) → User 리뷰 → 고화질 A. 버전 표식은 캡처 · 영상에서만 숨기고 촬영 HEAD를 기록.
### 3-6. 스토어 스크린샷 2차
같은 시드 · 같은 장면에서: 간판 아침 · 손님 도착 SALE · 트레이 + 가격 셋 · **같은 손님 NIGHT(영상과 같은 실제 결과)** · 마왕 토벌 · (옵션) ORDER. 영상과 스크린샷의 결과가 다르지 않게.

## 4. 배치 (순서만)
1. 시드 탐색(3-1) + 5초 시험 제작(3-2) + 6컷 첫 프레임 → User 리뷰(콘티 확정). 캡처 방법은 WORK 보고.
