## 2. 구현 방식 (핵심 메커니즘)

### 2-1. 그림 좌표계 — 잘린 배경 그림 위에 UI를 정확히 앉히기
- **문제:** 가게 방 배경은 `background-size:cover`라서 화면 비율에 따라 위아래나 좌우가 잘린다. 기존 UI는 "화면 %"로 배치돼 있어서, 잘리는 화면(바 있는 폰, 태블릿)에서 그림과 어긋났다.
- **해결:** 그림이 실제로 그려지는 높이를 CSS에서 계산한다.
  - 공식은 `--ph: max(100cqh, 100cqw / var(--ar))`이다(`--ar` = 그림 파일 비율: 세로 그림 .5628, 가로 그림 1.7768).
  - 그림 좌표 (x, y)는 화면에서 `50cqw + (x−.5)·--ph·--ar`, `50cqh + (y−.5)·--ph` 위치가 된다.
- **컨테이너 쿼리 단위(cq):**
  - `cqw`/`cqh`를 쓰려면 조상에 크기 컨테이너가 있어야 한다.
  - `.deco-layer`에 이어 이번에 **`.p-morning .store`에도 `container-type:size`를 추가**했다.
- **계산대 띠:**
  - `flex-basis: calc(var(--band-c) * var(--ph))`로 그림 비율대로 키운다.
  - `transform: translateY((--ph − 100cqh)/2)`로, 잘린 윗부분만큼 내린다.
  - 그림이 안 잘리면(`--ph`=`100cqh`) 이전과 수식상 같다. 그래서 폰과 데스크는 픽셀까지 동일하다.
- **함정:** CSS 변수 안의 `var()`는 선언한 요소에서 풀린다. 처음에 `--band-top`을 `.p-morning`에 선언했는데, `--ph`가 자식 `.store`에만 있어 값 전체가 무효가 됐다. `.store`로 옮겨 해결했다.

### 2-2. 화면 조건 분기
- **가로 그림 전환 조건:** `@media(min-width:1024px),(min-width:768px) and (min-height:700px) and (orientation:landscape)`
  - 이 문자열이 **3곳에 중복**된다(`director-review.css` 1곳, `ui.css` 2곳). 그림 관련 규칙이 함께 바뀌어야 해서다.
  - CSS에 custom media가 없어서 공통화하지 못했다.
- **높이 조건 분기:**
  - 명판 큰 크기: `min-height:760px`
  - 게시판 여유: `min-height:800px`
- **픽셀 글꼴 명판의 단계 조절:** `@container (min-height:800px) or (min-width:1000px)` 같은 컨테이너 쿼리를 쓴다.
  - 기준은 뷰포트가 아니라 게임 영역(`.store`)이다. 데스크는 게임 영역이 가로 1120px로 제한되기 때문이다.

### 2-3. 새 점포 준비 = 장면 (JS 구조 변경)
- **바뀐 것:**
  - 기존: 모달(`modal 'new'`)과 `newRun()`
  - 이후: `prepScreen()`이 MORNING과 같은 방 마크업을 그린다.
- **상태와 흐름:**
  - 상태 플래그 `prepOpen`을 새로 두었다.
  - `render()`는 런이 없거나(`!game.run`), 엔딩에서 `prepOpen`이면 이 장면을 그리고 바로 return한다.
  - 일찍 return하면 끝에 있는 코치 갱신을 건너뛰게 되므로, `showCoach`를 직접 부른다.
- **액션:**
  - 추가: `new`(엔딩 → 준비), `prep-back`(준비 → 엔딩)
  - 변경: `start`(런 시작 시 `prepOpen` 해제 + 새 사운드)
- **영향:** 기존 QA 도구 16개가 "게임 강제 시작 → 모달 클릭"을 전제하고 있었다. "시작 버튼이 화면에 있을 때만 누르고, 없으면 다시 그리기"로 바꿨다.

### 2-4. 주 버튼 — 그림자가 안 보이던 원인과 해결
- **원인:**
  - 버튼 모서리는 `clip-path`(노치 다각형)로 깎는다.
  - CSS는 filter(`drop-shadow`)를 **clip보다 먼저** 그린다. 그래서 선언된 그림자가 통째로 잘려, 버튼 7개에 그림자가 없었다.
  - 원래 코드 주석은 "그림자가 노치를 따라간다"고 적혀 있었지만 사실이 아니었다.
- **해결:**
  - clip 다각형을 "노치 면 ∪ 그림자 크기(`--nd`)만큼 밀린 같은 노치"로 넓혔다(20점 `calc` 다각형).
  - 누르면 `--nd:1px`로 바꾼다.
  - 7개 선택자가 이 규칙 하나를 공유한다. `:not([disabled])`로 비활성 상태는 제외했다.
- **정리:**
  - ORDER `영업 시작`은 자체 스타일을 지우고 `발주 확정` 규칙을 상속한다.
  - `첫 점포지원 고르기`는 자체 링 장식 box-shadow를 지우고 공통 `.stamp` 벽돌 규칙을 상속한다.

### 2-5. 크기 비례 (꼬리표, 명판)
- **꼬리표(일반 글꼴):**
  - 글자 크기는 `min(20px, max(11px, 1.72cqh, 1.4cqw))`이다. 360×640에서는 원래 크기이고, 큰 화면에서만 커진다.
  - 여백은 `em` 단위라 글자와 함께 커진다.
- **명판(픽셀 글꼴):** 12px 격자에서만 선명해서, 연속으로 키우지 않고 12 → 18 → 24px 단계로 키운다.
- **손가락 터치 영역:** SALE 점포지원 버튼은 보이는 크기를 24px로 줄였다. 대신 `:after{inset:-10px -4px}` 투명 영역으로 약 44px 터치를 유지한다.

### 2-6. 사운드
`audio.js`의 큐 표(`sfx`, `shape`)에 합성 큐 2개(`begin`, `newstore`)를 더하고, 액션 핸들러에서 호출하도록 연결했다. 새 에셋 파일은 없다.

## 4. 기술 부채 · 리스크 (솔직하게)

1. **그림 파일에 묶인 상수가 많다.** 배경 그림을 바꾸면 전부 다시 재야 한다.
   - 그림 좌표: 계산대 윗면 74.2~76%, 간판·액자 지점, 등록기 위치 비율 등
   - 레이아웃 가정값: `--dock-room:80px`(하단 버튼 높이 가정), `--plate-h:18/25px`(명판 높이 가정), 간판 꼬리표 `top:72%`(간판 그림 판 위치), 데스크 게임 영역 1120px
2. **미디어쿼리 문자열이 3곳에 중복**된다(2-2). 한 곳만 고치면 그림과 좌표가 어긋난다. 테스트가 세 곳이 같은지 확인한다.
3. **로드 순서와 명시도 의존**이 있다.
   - `director-review.css`가 뒤에 로드된다는 전제로 짜여 있다.
   - 등록기 위치는 인라인 스타일을 이기려고 `!important`(4개, 기존)를 쓴다.
   - 명시도를 올리는 선택자(`.p-morning.p-prep …`)가 늘었다.
4. **`.store`에 크기 컨테이너를 추가**했다. 자손의 %/cq 해석과 크기 격리가 달라진다. 지금은 `.store`가 flex:1이라 문제는 없지만, 나중에 내용 기반 높이를 기대하면 깨진다.
5. **공유 규칙의 파급이 있다.**
   - `.shelf-head` 여백 축소가 FINAL 상점 진열대 머리에도 적용된다(확인함).
   - 엔딩 모달의 `store-return` 버튼이 `첫 점포지원 고르기` 규칙을 공유해서 모양이 같이 바뀌었다(확인함).
6. **ui-guard의 문자열 고정 방식**은 CSS 리팩터 비용을 키운다. 이번 버전에서도 의도된 변경마다 정규식을 고쳐야 했다.
7. **기존부터 있던 것:**
   - `ui.css`에 어디서도 안 쓰는 `.p-start` 규칙 5개(v2.9.8 이전부터)
   - 역사 서술형 긴 CSS 주석
   - 비활성 SALE `손님 보내기`의 그림자 선언이 남아 있을 가능성(미확인)
