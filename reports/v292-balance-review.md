## 1. 하네스 재검토 — 절대 수치를 쓸 수 없는 이유

User는 fresh 첫 런에서 마왕까지 클리어했다. 반면 봇 정책은 현재 빌드(`base`)에서 이렇게 나온다.

| 정책 | D30 도달 | 클리어 | 종료 사유 (사망한도 / 파산·조기종료 / Final 실패 / 클리어) |
|---|---|---|---|
| balanced | 23.8% | 13.7% | 533 / 229 / 101 / 137 |
| human | 15.6% | 9.3% | 283 / 561 / 63 / 93 |

- 두 봇 모두 사람보다 확연히 약하다. 특히 운영(발주·현금 흐름)에서 무너진다. human 정책은 런의 56%를 파산·조기종료로 끝낸다.
- 따라서 "D30 도달 X%" 같은 기존 목표율에 숫자를 맞추는 판단은 무효다. 이 보고서는 **같은 정책 안에서 후보끼리의 상대 변화**만 쓴다.
- 두 정책은 성격이 다르다. balanced는 전투 쪽에서, human은 운영 쪽에서 약하다. 그런데도 두 정책 모두 **후보 순서가 같게** 나오면 그 순서는 신뢰할 수 있는 것으로 본다.

## 2. 인간형 정책 — 현재 상태와 제안

현재 `human` 정책은 `dist/systems/simulation.js`에 측정 전용으로 들어 있다. balanced를 기반으로 하고 두 가지가 다르다.
1. 부상 없고 피로 20 미만인 손님에게는 가방을 채운다(만반의 준비). 게이트 직접 가치가 낮은 아이템도 넣는다. 튜토리얼이 가르치는 행동이다.
2. 손님 지갑이 정가를 못 내면 언제든 50%로 내린다.

현금 하한(운영비만큼 남기기)도 시험했지만 뺐다. 선반이 비면서 파산 악순환이 생겼다.

결과: 사망 종료는 balanced의 절반(283 vs 533)으로 줄었다. 대신 파산·조기종료가 두 배 이상(561 vs 229)으로 늘었다.
**여전히 User 체감과는 거리가 멀다.** 휴리스틱만 계속 다듬어도 사람에게 가까워진다는 근거는 없다.

**제안 (User 결정 필요):** User 실제 플레이 1런으로 보정한다.
- User가 설정 → `저장 내보내기`로 D30(Final 직전) 또는 런 종료 직후의 저장 파일을 넘겨준다.
- 저장에는 NPC별 구매 기록(`n.history`: day, item, mode, paid)과 `stats`(revenue / spent / deaths), NPC 레벨·가방이 들어 있다.
  여기서 다음 값을 뽑아 human 정책의 목표값으로 삼는다.
  - 가격 모드 비율(50 / 정가 / 150)
  - 손님 1명당·하루당 판매 수
  - 일별 매출·지출 곡선
  - D20·D30 파티 레벨
  - 사망 수
- 보정 뒤에도 human 정책은 "상대 비교용 두 번째 렌즈"로만 쓴다. 최종 판단은 User 실제 플레이 체감으로 한다.

## 4. 해석

**대성공 EXP 1.10 (확정)**
- D30 최고 레벨이 약 0.7~0.9 내려간다(21.0 → 20.1~20.3). D20 상위 3명 평균도 12.9 → 12.5(balanced), 13.3 → 12.8(human)로 내려간다.
- 클리어는 약 25% 상대 감소한다(.137 → .103, .093 → .069). 감소 경로는 "도달 후 마왕전"이다. 도달 시 승률이 .58 → .50으로 떨어진다.
- 목적대로 스노우볼(상위 NPC 성장 속도)만 깎인다. 대성공 발생률(약 15%)과 도달률은 거의 그대로다.

**GATE SLOPE (A 1.40 / B 1.50)**
- 세 레버 중 영향이 가장 크다. A는 D30 도달을 약 절반(×0.46~0.47)으로 만든다. B는 ×0.27~0.38이다.
- 늘어나는 것은 "사망 한도 종료"다. 초중반 게이트가 세져서 D30 전에 무너진다. Final 실패는 오히려 줄어든다.
- A → B 차이(×0.47 → ×0.38 / ×0.46 → ×0.27)는 human 쪽에서 더 크다. 운영이 약한 플레이어일수록 B가 더 가파르게 느껴진다.

**정가 구매의사 (A ×0.90 / B ×0.80)**
- 실제 정가 수락률이 설계대로 줄어든다. 0.97 관련 준비 처리까지 포함한 전체 기준이다.
  - balanced: .861 → .774(×0.90) / .688(×0.80)
  - human: .845 → .758(×0.90) / .675(×0.80)
- 50% 수락률(약 .94~.95)과 150% 수락률(약 .59~.62)은 변하지 않는다.
- 효과는 주로 현금 쪽이다. 파산·조기종료가 늘고(balanced 286 → 284 / 337, human 557 → 611 / 617), D30 도달은 slope 위에 추가로 ×0.7~0.85 정도 더 줄어든다.
- A와 B의 도달률 차이는 작다(s14 기준 .072 vs .069, .045 vs .039). 차이는 주로 "현금 압박 체감"에서 난다.

**세 레버는 복리로 겹친다.** 가장 약한 조합(GS 1.10 + slope A + 정가 A)도 봇 기준 D30 도달이 현재의 약 30%로 떨어진다(balanced .238 → .072, human .156 → .045).
봇은 사람보다 훨씬 약하므로 사람에게 이 정도 감소가 그대로 오지는 않는다. 다만 방향과 순서는 두 렌즈 모두 같다.

## 5. 권고 (최종 결정은 User)

1. **1차 플레이 테스트 빌드: GS 1.10 + GATE SLOPE A(1.40) + 정가 A(×0.90).**
   세 레버가 겹치므로 가장 약한 조합부터 체감을 본다. 이 조합으로도 여전히 쉬우면, 영향이 큰 SLOPE를 B(1.50)로 먼저 올린다.
   정가 B는 도달률보다 현금 압박을 키우는 레버라서 그다음에 본다.
