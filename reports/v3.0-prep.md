#### 확인 방법 (새 도구 없이)
- `tests/acquisition.cjs`와 `tests/longitudinal.cjs`로 "END 한 줄이 비는 Run이 연속 몇 판 나오는가"를 센다. 신규 계정 기준으로 본다.
- **장식 획득 속도 — BALANCE FINDING 후보, 넛지와 분리해서 다룬다.**
  기준은 META §Approved progression expectation이다: 첫 장식 약 Run 4~6(v2.9.1 측정), 네 칸 약 Run 9(User 2026-09-24: Run 10~11까지).

  |---|---|---|
  | 싼 것부터 | 5 Run — 범위 안 | 17 Run — 늦음 |
  | 비싼 것부터 | 9 Run — 느림 | 19 Run — 늦음 |

  "전체가 약 2배 늦다"가 아니다. **첫 장식은 싼 순서면 기대 범위 안이고, 네 칸 완성이 확실히 늦다.**

### 3-2. 사운드 고도화 — AI로 어디까지 되나 (User 2026-09-28 요청, 리서치만. 결정 아님)

**지금 소리.** 배경음은 전부 코드로 합성한다(`dist/ui/audio.js` 시퀀서; 페이즈마다 템포·리드·베이스만 바꾼 한 엔진).

### 7-3. 가로로 돌린 폰 — PC 레이아웃을 가져다 쓸 수 있나 (2026-09-28 캡처 점검)

932x430(지금 가로 폰 화면)과 1024x430(PC 레이아웃을 같은 높이에 넣은 것)을 SALE · ORDER · NIGHT · MORNING으로 찍어 봤다.
- **안 된다. 막히는 건 폭이 아니라 높이(약 400px)다.** PC 레이아웃은 세로 약 800px 이상을 전제로 짜여 있다(1366x768 노트북에서도 진열대가 4줄만 보임).
  430 높이에 넣으면 SALE은 진열대가 한 줄도 안 보이고, ORDER는 합계 칸만 보이고 상품 행이 하나도 안 보인다.
- 지금 가로 폰 화면도 같다: SALE은 손님·목적지·능력치만 보이고 진열대가 화면 밖, NIGHT는 결과 카드가 잘린다.
  MORNING만 볼 만하다. 가로 화면에서 화면 QA 한 건(SALE 카드 묶음 크기)도 실패한다.
- 가로를 제대로 하려면 **가로 전용 배치**(왼쪽 손님·정보, 오른쪽 진열대, 버튼은 옆 세로 띠)가 따로 필요하다.
  이 배치는 Steam PC 화면에도 그대로 이어질 수 있다(가로 16:9 구성 하나를 크기만 바꿔 폰 가로 · 태블릿 가로 · PC에 쓰기). v3.x Steam 이식 때 같이 하는 게 맞다.
- **v3.0(모바일)은 세로 고정으로 간다.** 안드로이드 16(API 36)부터 태블릿·폴더블에서는 앱의 화면 방향 고정이 무시되지만,
  `android:appCategory="game"`인 게임은 예외라 세로 고정이 유지된다. 구글 플레이는 2026-08-31부터 새 앱과 업데이트에 API 36 타깃을 요구한다.

출처: [Android 16 화면 방향 변경](https://android-developers.googleblog.com/2025/01/orientation-and-resizability-changes-in-android-16.html) ·
[구글 플레이 타깃 API 요건](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en)
