### 3-1. Cross-run 반복 플레이 연결 — User 방향 2026-09-26

목표는 새 반복 플레이 시스템을 하나 더 만드는 것이 아니라, **현재 이미 존재하는 Meta 진행을 Run 종료 → 다음 Run 준비로 연결해 플레이어가 "한 판 더 하면 무엇이 가까워지는지" 읽게 하는 것**이다.

이 항목은 아직 Current Design SSOT가 아니다. `META_v2.8.0.md`의 기존 Cross-run 구조를 재사용하는 v3.0 준비 방향이며, 실제 구현 전에는 해당 owner / QA로 승격해야 한다.

#### A. END = Cross-run 결산의 단일 진입점

중도 자연 종료, FINAL 실패, CLEAR를 별도 반복 시스템으로 나누지 않는다. 현재 공통 END 흐름을 유지하고, **이번 Run에서 실제로 계정에 남은 변화만** 한 블록으로 묶어 보여준다.

재사용 대상:
- Store Capital 정산
- Monster / Family Knowledge 변화
- 현재 Canonical의 영구 상품 해금
- CLEAR에서 실제 발생한 Job × Boss matrix 진행
- 그 밖에 이미 Account Save에 존재하는 승인된 Meta 변화

원칙:
- 실패용 별도 화폐 / 위로 보상 / 영구 Power를 만들지 않는다.
- CLEAR 전용 화면을 따로 만들어 Cross-run 흐름을 갈라놓지 않는다.
- 이번 Run에서 실제로 변하지 않은 값은 성취처럼 포장하지 않는다.
- 기존 END의 결과 / 실패 사유 / 정산 의미를 지우지 않는다.

Player-facing 역할:
`이번 점포에서 무엇을 했는가 → 그중 무엇이 계정에 남았는가`

#### B. END에서 기존 Meta의 "다음 목표"를 1~2개만 연결

END의 마지막 CTA 근처에서 새 퀘스트를 발급하지 않고, **이미 존재하는 장기 진행 중 다음 Run과 직접 연결되는 실제 목표**를 짧게 보여준다.

후보:
- 현재 Store Capital과 아직 구매하지 않은 Decoration
- Distinct Boss Clear 기반의 기존 unlock 진행
- 아직 비어 있는 Job × Boss matrix 진행

원칙:
- 새 Mission / Daily / Weekly / Ascension 트랙을 만들지 않는다.
- 플레이어 대신 "정답 빌드"나 다음 Run 운영법을 추천하지 않는다.
- 실패 원인을 분석해 `다음에는 회복 빌드를 하라` 같은 전술 지시를 만들지 않는다.
- 한 번에 많은 미완료 목표를 열거하지 않는다. 1~2개의 실제 진행만 보여준다.
- Meta 진행이 없는 Run이면 없는 것을 억지로 만들지 않는다.

Player-facing 역할:
`이번 Run도 남은 것이 있다 → 다음 Run에서 무엇이 가까워지는지 안다`

#### C. 새 점포 준비에서 같은 Cross-run 상태를 이어서 보여주기

END에서 본 Meta 진행을 새 점포 준비에서 다시 찾을 수 있어야 한다. 새 시스템을 추가하지 않고 기존 Account state를 요약한다.

표시 후보:
- 현재 Store Capital
- 보유 / 장착 Decoration 상태
- Distinct Boss Clear / 승인된 unlock 진행
- Job Mastery / matrix 진척의 compact entry

원칙:
- Pre-run 화면을 장부 / 대시보드로 과밀하게 만들지 않는다.
- Decoration 구매 우선순위를 게임이 대신 정하지 않는다.
- END와 Pre-run이 서로 다른 진행 숫자를 만들지 않는다. 둘 다 같은 Account truth를 읽는다.
- 새 persistent field를 만들기 전에 현재 Account Save로 전부 파생 가능한지 먼저 본다.

목표 흐름:
```text
Run
→ END에서 이번 Run의 영구 변화 확인
→ 기존 Meta에서 다음에 가까워질 목표 확인
→ 새 점포 준비에서 같은 진행을 이어서 봄
→ 다음 Run
```

#### D. Cross-run 곡선은 "Power"뿐 아니라 "의미 있는 사건 간격"도 측정

§4의 Cross-run 재측정에서는 Final 접근률만 보지 않는다. 반복 플레이 관점에서 아래도 함께 기록한다.

- 첫 Decoration 구매까지 실제 Run 수
- 네 Slot을 채우는 실제 Run 수
- 이후 두 번째 Decoration 수집의 간격
- Distinct Boss unlock 사이의 실제 Run 간격
- Job × Boss matrix가 새로 채워지는 빈도
- 몇 Run 연속으로 구매 / 해금 / matrix 진척 없이 Store Capital 숫자만 증가하는 구간이 생기는지

목적은 보상을 억지로 자주 뿌리는 것이 아니라, **현재 Meta 구조에 반복 동기가 비는 구간이 실제로 있는지 확인하는 것**이다.

측정 결과 공백이 있어도 자동으로 신규 시스템을 추가하지 않는다.

```text
측정
→ 실제 반복 동기 공백 확인
→ 기존 Meta / 가격 / 표시 / 연결로 해결 가능한지 먼저 검토
→ 그래도 부족할 때만 v3.0+ 구조 후보를 User가 판단
```

#### E. v3.0+ 기존 후보와의 경계

- §15 Expanded Store-Build Axes의 목표인 `이번 판은 어떤 편의점이었는가?`와 직접 연결된다. END는 그 Run identity를 결산하는 위치로 본다.
- Router의 `어제보다 +N` CLOSING 후보는 **Run 내부의 Day-to-Day short loop**다. 이 항목은 **Run-to-Run Cross-run loop**이므로 역할이 다르다.
- §1 원정 목적, §16 단골 관계 심화, §17 Final / Boss 콘텐츠 확장을 이 항목만으로 승격하지 않는다.
- §13 New Meta Power Progression의 기본 거부 원칙을 유지한다. 반복 동기를 이유로 failure currency / account-wide raw Power를 추가하지 않는다.

   그 밖의 공개 조건(타이틀·크레딧·저작권 고지·오류 보고 경로 등)은 아직 어떤 owner에도 정의돼 있지 않다 → **UNRESOLVED**. User가 목록을 정해야 한다.
