## 2. v2.9.x에서 넘어온 열린 항목 (결정 전, 손대지 않음)

### 2-1. 밸런스
1. **4차 빌드 실플레이 확인이 먼저다.** User 세이브 2개는 모두 2차 조정 전 빌드였다. 플레이 데이터를 줄 때 첫 화면의 `v2.9.3 · 커밋`을 같이 받는다.
2. **Final 확정승 여유**(GPT 리뷰 제기): 세이브에서 파티 221 / 보스 180이었고, 최저 roll 0.88에서도 승리했다. 봇 숙련 코호트는 1.06~1.12다.
   후보 레버는 Final 보스 Power, 핵심 3인의 성장 집중, Hazard 준비가 Final 결과에 반영되는 비중이다. 수치 결정은 User 몫이다.
3. **RoyalCert 후반 경제**(GPT 리뷰 제기): 세이브에서 D15 이후 수수료 3,432G가 들어왔고, 리롤에 3,600G를 썼다. 운영비보다 먼저 감사할 후보다.
4. **핵심 3인 집중**(GPT 리뷰 제기): 세이브에서 3명이 원정의 35%, EXP의 약 46.5%, 장비 Power의 약 85%를 가져갔다. 생존한 실패에서 나온 EXP가 전체의 47.8%였다.
   EXP를 다시 건드리는 건 비추천이라는 판단을 받았다(2026-09-26).
5. Level 사망 보정은 4차에서 제거했다. 사망 수가 과해지는지 실플레이로 본다.

### 3-1. 다회차 넛지 — "한 판 더"가 자연스럽게 (User 방향 2026-09-26, WORK 기획안 · 결정 전)

> Design이 아니다. 채택하면 UI_UX / META / COPY_AUDIT owner로 승격한 뒤 구현한다.

**원칙: 보여주기만 하고, 시키지 않는다.**
- 과제 목록 · 진행 바 · `N / 42` 같은 남은 개수 · 미션 · 일일 보상 · 실패 화폐 · 새 영구 파워는 **만들지 않는다**(§13 유지).
- 화면마다 **한 줄**만 둔다. 가게 영수증과 길드 공지 말투로 쓴다. 이미 일어났거나 지금 할 수 있는 **사실**만 말한다. "~하세요"라고 쓰지 않는다.
- 해당하는 게 없으면 **아무것도 띄우지 않는다.** 빈 칸을 억지로 채우지 않는다.

#### 최소안 (GPT 리뷰 반영, 2026-09-26)

| 어디서 | 무엇을 | 새 상태 |
|---|---|---|
| **END 영수증 맨 아래**, `다음 점포 열기` 바로 위 | 이번 Run에 실제로 일어난 것 중 **한 줄**. 아래 우선순위에서 처음 맞는 것, 없으면 없음 | 아래 참고 |
| **새 점포 준비** | 지금 자본으로 살 수 있는 미보유 장식이 자연스럽게 읽히게만 한다. 이미 구매 버튼이 활성화되고 가격이 보이므로, **시각 확인 후 부족할 때만** 현재 상태 표시(`들일 수 있음`)를 붙인다. "새로" 여부는 추적하지 않는다 | 없음 |
| **도감** | 그대로. NEW 점은 넣지 않는다(읽음 상태가 따로 필요하고, END에 이미 `도감에서 보기`가 있다) | 없음 |

END 한 줄 우선순위:
1. **이번 Run에 새로 열린 것.**
   - 마왕 클리어 해금: 지금도 `run.unlocked`에 남아 `본사 해금`에 나온다.
   - D10·D14 첫 도달 해금(길드 특제 도시락 · 세계수 생환부적): 지금은 account 값만 켜고 `run.toast`로 한 번 띄운 뒤 지운다. 그래서 END가 알 수 없다.
     같은 줄에 합치려면 **Run 안의 해금 기록 하나**가 필요하다(`run.unlocked`에 같이 넣는 방식이 가장 작다). 이게 싫으면 이 해금은 END에서 빼고 토스트만 둔다.
2. **점포 자본으로 새 장식을 들일 수 있게 됐다.** 예: `점포 자본으로 새 장식을 들일 수 있다.`
   - 특정 장식 이름은 쓰지 않는다. 칸마다 두 가지 선택지가 있어서 이름을 쓰면 게임이 추천하는 것처럼 읽힌다.
   - END 정산 count-up은 장식 가격선을 넘을 때 이미 `ui` 클릭을 낸다(H4). 이 줄은 그 피드백을 말로 굳히는 수준이다.
3. **계정 최고 도달일 갱신.** 예: `이 지점에서 가장 오래 버틴 점포다 · DAY 17`
   - 이전 기록을 **넘었을 때만** 띄운다(같은 날은 제외).
   - **자연 종료로만 갱신한다.** 수동 `현재 지점 포기`는 `end()`에 닿지 않으므로 갱신도 없다. 그래서 DAY 29에서 포기해도 최고 기록이 찍히지 않는다.
   - 기록이 없는 첫 Run은 갱신으로 치지 않는다(첫 판마다 뜨는 줄이 되지 않도록).

지금 END에 이미 있는 것은 그대로 둔다: 점포 자본 정산, CLEAR 때 직업 숙련 변화, `본사 해금`, `지금까지 연 점포 N`.

#### 필요한 것 (작다)
- 새 영구 저장 값: **`bestDay` 하나**(account).
- D10·D14를 END에 합칠 경우에만 Run 범위 기록 하나(`run.unlocked`에 추가).
- 새 화면·버튼·연출 없음. 문구 2~3줄은 COPY_AUDIT 승인을 받는다.

#### 확인 방법 (새 도구 없이)
- `tests/acquisition.cjs`와 `tests/longitudinal.cjs`로 "END 한 줄이 비는 Run이 연속 몇 판 나오는가"를 센다. 신규 계정 기준으로 본다.
- **장식 획득 속도 — BALANCE FINDING 후보, 넛지와 분리해서 다룬다.**
  기준은 META §Approved progression expectation이다: 첫 장식 약 Run 4~6(v2.9.1 측정), 네 칸 약 Run 9(User 2026-09-24: Run 10~11까지).
  현재 소스로 잰 값(balanced 봇, 120궤적 × 20 Run):

  | 구매 순서 | 첫 장식 | 네 칸 완성 |
  |---|---|---|
  | 싼 것부터 | 5 Run — 범위 안 | 17 Run — 늦음 |
  | 비싼 것부터 | 9 Run — 느림 | 19 Run — 늦음 |

  "전체가 약 2배 늦다"가 아니다. **첫 장식은 싼 순서면 기대 범위 안이고, 네 칸 완성이 확실히 늦다.**
  봇이 사람보다 약하다는 점을 감안한다. 수치는 User가 정한다.
  (`tests/acquisition.cjs`가 출력하던 "승인된 기대 3~4 / 6 / 8~9 / 10~11"은 2026-09-19에 박아 둔 옛 문구였다. META 값을 인용하도록 고쳤다.)

#### 경계
- `어제보다 +N`(보류 후보)은 Run 안의 하루 단위 루프다. 이 넛지는 Run과 Run 사이의 루프라서 역할이 겹치지 않는다.
- 원정 목적(§1) · 단골 관계(§16) · Final 확장(§17)은 이 기획만으로 승격하지 않는다. 연결되는 것은 §15 "이번 판은 어떤 편의점이었나"뿐이다.
