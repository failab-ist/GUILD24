## 0. v3.0이 무엇인가 (Canonical에 이미 정해진 것)

- **v3.0.0 = 외부 공개 릴리스 목표.** 근거: SPEC_INDEX 헤더 `EXTERNAL_PUBLIC_RELEASE_TARGET=v3.0.0`, CORE_RUN §release-policy, META §PRE-RELEASE COMPATIBILITY POLICY.
- v2.x는 내부 개발·테스트 라인이다. 그래서 지금은 옛 Save를 이관하지 않는다(v1~v7은 이관 없이 새로 시작).
  **v3.0.0부터는 이 전제가 바뀐다.** 공개 뒤에는 플레이어 Save를 지켜야 하므로, 호환성 경계를 v3.0.0에서 새로 세워야 한다(META: "the v3.0.0 external-release compatibility boundary").
- 구조 확장(P2+)은 보류 후보 문서의 **§19 진입 조건**을 통과해야만 승격할 수 있다.
  - v2.8 정보 신뢰 문제가 닫혔는가
  - 점포 빌드 효과를 플레이어가 이해하는가
  - 피로를 읽고 쓰는가
  - SALE → NIGHT 인과가 읽히는가
  - 마왕이 Run 내내 보이는가
  - 남은 전략 수렴이 연출 문제가 아니라 실제 문제인가

## 2. v2.9.x에서 넘어온 열린 항목 (결정 전, 손대지 않음)

### 2-1. 밸런스
1. **4차 빌드 실플레이 확인이 먼저다.** User 세이브 2개는 모두 2차 조정 전 빌드였다. 플레이 데이터를 줄 때 첫 화면의 `v2.9.3 · 커밋`을 같이 받는다.
2. **Final 확정승 여유**(GPT 리뷰 제기): 세이브에서 파티 221 / 보스 180이었고, 최저 roll 0.88에서도 승리했다. 봇 숙련 코호트는 1.06~1.12다.
   후보 레버는 Final 보스 Power, 핵심 3인의 성장 집중, Hazard 준비가 Final 결과에 반영되는 비중이다. 수치 결정은 User 몫이다.
3. **RoyalCert 후반 경제**(GPT 리뷰 제기): 세이브에서 D15 이후 수수료 3,432G가 들어왔고, 리롤에 3,600G를 썼다. 운영비보다 먼저 감사할 후보다.
4. **핵심 3인 집중**(GPT 리뷰 제기): 세이브에서 3명이 원정의 35%, EXP의 약 46.5%, 장비 Power의 약 85%를 가져갔다. 생존한 실패에서 나온 EXP가 전체의 47.8%였다.
   EXP를 다시 건드리는 건 비추천이라는 판단을 받았다(2026-09-26).
5. Level 사망 보정은 4차에서 제거했다. 사망 수가 과해지는지 실플레이로 본다.

### 2-2. UX 재확인 — 닫힘
6건(SALE 트레이 접기 · 발주 플로팅 오늘 줄 · 게이트 방문 최소 1명 · D30 흐름 · 진열대 요약 문구 · H5 봉인 세부)은 User가 2026-09-26 v2.9.3에서 현재 구현대로 확정했다.

## 4. WORK 추천 순서 (결정 아님)

1. **v2.9.3 실플레이 데이터 수집.** fresh 1~2판, D30 직후 또는 런 종료 직후에 저장. 커밋 번호도 같이 받는다.
2. **v2.9.4 밸런스 감사(측정 전용 → User 결정).** Final 여유와 RoyalCert를 쌍 비교로 잰다.
   측정 틀은 `archive/v2.9.2/tools/measure-package-v292.cjs`를 본떠 새로 만든다. 봇 보정은 `tools/calibrate-bot-v292.cjs`로 한다.
3. **Cross-run 곡선 측정.** Difficulty Curve의 "장식 전부 보유" 두 줄을 v2.9 이후 값으로 다시 잰다. 공개 릴리스의 반복 플레이 경험을 결정한다.
4. **§19 진입 조건 점검.** 플레이 증거로 여섯 항목을 판정한 뒤에만 §3 후보 중 무엇을 승격할지 User가 고른다.
5. **공개 릴리스 준비(v3.0.0).** Save 호환성 경계를 새로 정하는 것이 필수다(공개 뒤 Save 이관 정책, Save 버전).
   빌드 표식(첫 화면 `v{version} · {commit}`)은 이미 있다.
   그 밖의 공개 조건(타이틀·크레딧·저작권 고지·오류 보고 경로 등)은 아직 어떤 owner에도 정의돼 있지 않다 → **UNRESOLVED**. User가 목록을 정해야 한다.
