# 직업 비교 도구

`measure-jobs.cjs`는 직업의 초기 능력치와 성장만 비교한다. 현재 Source를 기준으로 `job-balance-candidate.json`의 승인 후보를 메모리에 적용하고, 처리 후 원래 값과 함수 참조를 복구한다. Production 파일·사용자 세이브는 변경하지 않는다. 게임의 `prepare`, `resolve`, `grow`, Gate 생성, 회복 처리와 기존 reader/expert 봇을 재사용한다.

입력 후보는 기존 직업 id의 `stats`와 `growth`(투력 / 강인함 / 기동 / 정신)만 허용한다. 생략한 직업은 실행 시점 Source를 상속한다. 자동 수치 탐색·자동 PASS 판정은 없다.

## 제작 검증과 실행 계획

```powershell
node tests/job-balance-tool.cjs
node tools/measure-jobs.cjs --help
node tools/measure-jobs.cjs --mode plan
```

위 명령은 밸런스 시뮬레이션을 돌리지 않는다. 테스트의 고정 원정 1건은 판정 연결을 확인하는 회귀 검사이며 성과 측정이 아니다. `plan`은 모든 모드의 규모와 후보 값을 출력한다. 실행 시간은 아직 측정하지 않았으므로 임의로 예상 시간을 넣지 않는다.

`stats`는 초기·Lv5/10/15/20 전력, 전력 성장, 9종 위험 대응을 같은 잠재력에서 계산한다. 실제 NPC 초기 생성은 반올림하지만 산술 비교표는 반올림 전 선형값이다.

## 측정 모드

AGENTS §9-A에 따라 명령·정책·규모·예상 시간을 보고하고 User 확인 후에만 측정한다. 아래는 사용법이며 실행 승인이 아니다.

```powershell
node tools/measure-jobs.cjs --mode expeditions --samples 100 --execute --out reports/jobs-expeditions.json
node tools/measure-jobs.cjs --mode growth --samples 100 --execute --out reports/jobs-growth.json
node tools/measure-jobs.cjs --mode runs --runs 100 --policies reader,expert --execute --out reports/jobs-runs.json
```

결과는 JSON과 동명의 한글 Markdown으로 저장한다. 기존 결과를 덮어쓰지 않는다. Source/설계/테스트/도구 경로에는 결과를 쓸 수 없다. Source 해시와 HEAD, 후보 전체 값, 입력과 실제 실행 시간을 기록하고, 실행 중 Source가 바뀌면 결과 저장을 거부한다.

### 독립 원정 — `expeditions`

- 기준 Source와 후보 × 6직업 × 4단계 × 5 Family × 건강/부상·피로 상태 × 3보급 정책 × samples.
- 비교 단계는 D4/Lv2/T1, D14/Lv6/T2, D21/Lv10/T2, D29/Lv15/T3이다. 같은 단계에서 직업만 다르며 실제 평균 레벨이나 밸런스 목표를 뜻하지 않는다.
- 건강은 부상0·피로0, 상태 악화는 부상1·피로25다. 장비0, 점포지원·장식·사건·첫 런 보호·숨은 지원은 없다.
- 기본 잠재력1·희귀도0·특성 없음. `--potential`, `--rarity`, `--traits`로 모두 같은 조건을 지정할 수 있다.
- 같은 사례/표본의 시드는 직업·후보와 독립이다. 전투/환경의 첫 추첨을 공유하지만, 조건 분기 후 모든 추첨이 같은 위치에 남는다는 보장은 없다.
- 성공·전투 승리·환경 사고·사망·준비/요구·EXP·전리품과 사용 상품/비용을 기록한다.

보급은 `none`(없음), `same`(간단 도시락+하급 포션), `budget`(같은 매입가 예산)이다. 기본 예산은200G다. `same`이 예산을 넘으면 빈 가방이며 정책별 실제 상품/비용을 기록한다. `budget`은 해금 상품을 제외한 현재 상품의 0~2개 조합(중복 포함)을 열거하고, 준비 전력의 전투 승률×환경 무사 확률×부상 판정 통과 추정값이 가장 높은 조합을 선택한다. 동점이면 싼 조합을 고른다. 상품 획득·재고·지갑·보험까지의 최적 전략을 의미하지 않는다. 이 한계를 실제 영업 비교와 함께 읽는다.

### 누적 성장 — `growth`

기준/후보 × 6직업 × 3보급 정책 × samples의 한 손님 궤적이다. Lv1에서 시작해 D1~29의 같은 Family/Tier 일정을 주고 실제 EXP·성장·장비·부상·피로·사망을 누적한다. 중상 회복은 아침 처리와 같이 적용하며 회복 기간에는 출발하지 않는다. 사망한 손님을 교체하거나 살려내지 않는다. 장식·자연 피로 회복은 추가하지 않는다.

비용은 매일 같은 외부 보급 예산이며 지갑을 깎지 않는다. 따라서 이 모드는 성장/상태 스노우볼을 분리한 실험이고 실제 영업이나 재방문을 재현하지 않는다. 구간 결과와 D7/14/21/29의 능력치·장비·피로·부상·지갑을 회복 중인 날도 저장한다. 사망하면 그날 마지막 상태를 저장하고 궤적을 종료한다.

### 실제 영업 — `runs`

기준/후보 × reader/expert × 6직업 혼합+직업별 단일 구성(7조건) × runs. 기본100이면 총2,800런이다. 같은 희귀도·잠재력·특성을 모든 신규 손님에게 적용한다. 해금은 전부 켜고 숙련은0으로 통제하므로 실제 계정의 해금 진행과 구분한다. 첫 런 보호는 기본OFF, `--first-run`으로ON을 명시할 수 있다. 단일 구성은 모든 신규 손님을 해당 직업으로 바꾼 실험이며 실제 일반 로스터를 뜻하지 않는다.

기존 봇의 영업·상품 접근·지갑·재방문·점포지원·최종 선발을 그대로 사용한다. 신규 손님의 일차별 레벨 추첨은 Source를 따른다. 시드 집합과 정책은 같지만 다른 판정 결과 뒤의 방문/사건/추첨까지 동일하게 고정됐다는 뜻은 아니다. 구간 성공, 생존·성장, D30 도달/클리어, 사망, 최종 직업 기여와 표본을 JSON으로 남긴다.

이 도구는 직업 비교 실험이다. 전체 게임의 기준 밸런스 판단은 기존 `tools/measure-v2100.cjs`(AGENTS §9-B)로 확인한다. 도구의 숫자는 User의 컨셉·해금 우위·준비 부담 목표를 대신 결정하지 않는다.
